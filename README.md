# kzn-form-tool

3人チームで開発を進めるためのリポジトリです。

## はじめに
1. 開発の流れ・ブランチ運用は [CONTRIBUTING.md](CONTRIBUTING.md) を読んでください。
2. Claude Code(クラウド)で開発する場合は [CLAUDE.md](CLAUDE.md) がClaudeへの共通指示になります。
3. 開発環境のセットアップ手順は下記「セットアップ」に追記してください。

## ツール概要
Zoom商談の文字起こしから制作発注書の項目を自動抽出し、確認・修正のうえHubSpotへ転記する単一HTMLツールです(`index.html`)。

### 使い方
1. ツールを開くと「今回の案件はどちらですか？」が出るので、**nest** か **RAQMO** を選びます(URLに `?product=nest` / `?product=raqmo` を付けると、この画面を飛ばして開けます)。
   - 選ぶ前に、お客様に見せた資料・サイトのURL、既存サイト、Instagram・X・Facebook、GoogleビジネスプロフィールのURLを、まとめて貼り付けられます。種類は自動で振り分けられ(画面で変更可)、商材を選んだ時点で発注書の該当欄に転記されます。nestでは各SNS・GBP・既存サイト・提示資料の欄へ、RAQMOでは参考サイトURL・MEETOのインスタ・備考へ入ります。手入力した欄や、あとの解析結果では上書きされません。
2. Zoomの文字起こし(`.vtt` / `.txt`)をドロップする、貼り付ける、または「クリップボードから取り込む」を押します。読み込んだ時点で自動解析され、右の「制作発注書プレビュー」が埋まります。
3. 抽出結果を目視で確認・修正します(必須項目の未入力は赤い「未確定(要確認)」で表示)。
4. 「HubSpotにチケットを作成して転記」を押すと、発注書が新しいチケットとして作られ、指定した取引と会社に紐づきます。

### 画面の構成
- 上部: ツール名、選んだ商材、「案件を選び直す」。
- 左: ①Zoomの文字起こし(貼り付け・ドロップ・クリップボード、話者の役割)、②AI解析の設定(折りたたみ、任意)、③HubSpot接続設定(折りたたみ)。PCでは、スクロールしても左が追従します。
- 右: ④発注書プレビュー。基本情報のあと、セクションごとのカードに分かれます。横に並んだ欄は2列で、対象外のセクション(例: フルパック以外のAUTO関連)は畳んで表示し、見出しを押すと開閉できます。
- 右下: 操作バー(不足確認文のコピー、発注書のコピー、HubSpotへ転記)は、スクロールしても画面下に固定されます。
- 必須項目は、解析する前は「*」だけ表示します。解析(または不足確認文のコピー)をすると、未入力の必須項目が「未確定」として強調されます。
- スマホ幅では1列になります。画面のスタイルは、このファイル内のCSSで定義していて、Tailwind(CDN)が読み込めなくても崩れません。

### 商材ごとのプレビュー項目
- **nest**: nestの発注ひな形の全項目(受注・販促商品/nest本体/AUTO/AIO/AIO-RAQMO付/イレギュラー)。契約プランに応じて必須項目が変わります。更新頻度は言及がなければ「半年」。
- **RAQMO**: 制作発注の項目(案件概要・ターゲット・トンマナ・参考URL・提供素材)と、販促(MEETO・MOEL・MOFUL)の詳細。●をつけた販促だけ詳細が必須になります。
- **その他**: 制作発注の項目のみ。

### 自動解析の考え方
- 文字起こしの話者を「営業」「お客様」に分け、**お客様の発言を優先**して項目を埋めます。話者の役割は画面で変更でき(変更後は「自動解析」を押し直す)、「担当営業」と同じ名前の話者は営業とみなします。
- **営業が提案し、お客様がうなずいた内容**(「はい」「そうですね」「お願いします」などの返事)は、お客様の希望として案件概要・ターゲット・トンマナに採用します。「いえ」「ちょっと違う」「検討します」など、否定・保留の返事が付いた提案は採用しません。うなずきは、直前の営業の発言だけに対するものとして扱います。
- 拾った発言は、発注書に載せて意味が通る言い切りの文に整えます(例: 「えーと、ターゲットは学生さんですよね。」→「ターゲットは学生さんです。」、「〜ということでよろしいでしょうか」→「〜」)。長い文は読点の位置で省略します。
- Zoomの字幕が1文の途中で区切られている場合は、同じ話者の続きの字幕をつないで1文に戻して解析します。
- 手入力した欄は、文字起こしを貼り直しても上書きしません(自動入力のままの欄は更新されます)。複数行の欄は内容に合わせて高さが広がります。
- nestでは、業種・事業内容・店舗情報(住所・営業時間の語尾は整形)・SNSを「やっていない」場合の「なし」・GBPのオーナー権限・公式LINEの登録状況も拾います(営業の確認の質問だけでは埋めません)。
- 初期設定の解析は、すべてブラウザ内のルール処理で、AI(トークン)も外部送信も使いません。精度を上げたいときは、次の「AI解析(任意)」をオンにします。
- KIZUNAのサービス紹介・料金の説明は、案件概要などに入れません。お客様の発言が無い項目は、営業の「お客様向けの提案」を `【営業発言】` と明記して補います。それも無い項目は空欄のまま(未確定)にします。
- ログイン用メール・パスワード等の認証情報は自動抽出しません。

### AI解析(任意・初期値はオフ)
会話の流れを読んで、お客様の事業・強み・困りごと・やりたいこと・要望などを発注書に入れる精度を上げる機能です。規則ベースでは拾いにくい、言い換え・訂正・うなずきを含む会話の流れを、AI(Claude)が読みます。
- **使い方**: 左カラム「2. AI解析の設定」で「解析のときにAIも使う」をオンにし、Anthropic APIキーを入力します(「保存する」を選ぶと、このブラウザのLocalStorageにだけ保存されます)。あとは、いつもどおり文字起こしを入れる/貼り付けると、規則ベースの結果が先に入り、続けてAIが読み取った内容が反映されます。
- **送信される情報**: オンにしたときだけ、**文字起こしと項目の定義**が Anthropic のAPI(api.anthropic.com)へ送信されます。お客様の情報が含まれるため、社内の取り扱いルールに沿って使ってください。APIキーは、このブラウザにだけ保存され、Anthropic以外へは送信しません。
- **反映のルール**: AIが入れた欄には「AI抽出・要目視確認」が付きます。手入力した欄、起動時に貼ったURL、認証情報(メール・パスワード)の欄は、上書きしません(認証情報の欄はAIに渡しません)。選択式の欄は、選択肢にない値を反映しません。AIが失敗しても、規則ベースの結果は残ります。同じ内容は再送しません。
- **料金**: 解析ごとにAPI利用料がかかります。解析後に、使ったトークン数を表示します。モデルは、Claude Opus 5.5(高精度・標準)、Sonnet 5.5(速い・低コスト)、Haiku 5.5(最安・簡易)から選べます。
- **AIからの確認事項**: 音声認識の誤りが疑われる固有名詞・電話番号・住所などを、結果の下に表示します。

### HubSpotへの転記
- **取引ID(必須)**: 発注書のチケットを紐づける取引。HubSpotの取引画面のURL末尾の数字です。
- **会社ID(任意)**: 空にすると、取引に紐づく会社を自動で取得します。
- 接続設定(トークン、チケット本文のプロパティ名、パイプラインID、ステージID)は左カラム「3. HubSpot接続設定」。パイプライン・ステージはチケット作成に必須で、初期値は標準の「0」「1」です。

### 実行・技術・注意
- 実行: `index.html` をブラウザで開くだけ(Node.js・サーバー不要)。
- 技術: HTML / Tailwind CSS(CDN) / 素のJavaScript。初期設定の抽出はルールベースでAI・外部送信なし(AI解析をオンにしたときだけ、Anthropic APIを呼びます)。
- HubSpotトークンは画面で一時入力、またはブラウザのLocalStorageに保存(HubSpot API以外には送信しません)。
- 注意: HubSpot APIをブラウザから直接呼ぶとCORSで失敗する場合があります。その場合は「発注書をコピー」で手動貼り付けしてください。

## 発注書変換スキル(Claude Code)
Zoom文字起こしを発注書に変換する、**種類別の専用スキル**です。種類ごとに完全に分離しており、書式・ルールは混ざりません。

| コマンド | 対象 | 見出し |
|---|---|---|
| `/order-raqmo` | RAQMO(制作発注) | 【制作発注】 |
| `/order-nest` | nestの発注 | 【nestの発注】 |

- 使い方: `/order-nest` の後ろに文字起こしを貼る(または実行後に貼る)。出力は「発注書本文」と「要確認リスト」。
- 自動では起動しません(`disable-model-invocation`)。必ずコマンドで種類を選んでください。
- 場所: `.claude/skills/order-raqmo/` と `.claude/skills/order-nest/`(各 `SKILL.md`=変換ルール、`template.md`=書式、`learning.md`=過去事例の学習メモ)。
- 種類の見分け方: 「nest / フルパック / AIO / 口コミ誘導」が出ればnest、「ドメイン / MEETO / MOFUL / サイト名」が出ればRAQMO。
- nestにRAQMO-LP(AIO付)が付く場合は、nestの発注書内の【AIO-RAQMO付の場合】欄に書きます(RAQMO書式は使わない)。別契約なら2通に分けて作成します。
- パスワードの扱いは種類で異なります(RAQMO=書かない、nest=お客様が明言した場合のみ記入)。発注書には機微情報が入りうるため、Gitや共有チャットに貼らないでください。

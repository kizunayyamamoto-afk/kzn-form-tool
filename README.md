# kzn-form-tool

3人チームで開発を進めるためのリポジトリです。

## はじめに
1. 開発の流れ・ブランチ運用は [CONTRIBUTING.md](CONTRIBUTING.md) を読んでください。
2. Claude Code(クラウド)で開発する場合は [CLAUDE.md](CLAUDE.md) がClaudeへの共通指示になります。
3. 開発環境のセットアップ手順は下記「セットアップ」に追記してください。

## ツール概要
Zoom商談の文字起こしから制作発注書の項目を自動抽出し、確認・修正のうえHubSpotへ転記する単一HTMLツールです(`index.html`)。

### 使い方
1. ツールを開くと「今回の案件はどちらですか？」が出るので、**nest** か **RAQMO** を選びます(URLに `?product=nest` / `?product=raqmo` を付けると、この画面を飛ばして開けます)。
   - 選ぶ前に、お客様に見せた資料・サイトのURL、既存サイト、Instagram・X・Facebook、GoogleビジネスプロフィールのURLを、まとめて貼り付けられます。種類は自動で振り分けられ(画面で変更可)、商材を選んだ時点で発注書の該当欄に転記されます。nestでは各SNS・GBP・既存サイト・提示資料の欄へ、RAQMOでは参考サイトURL・MEETOのインスタ・備考へ入ります。手入力した欄や、あとの解析結果では上書きされません。
2. 左の「Zoom要約・URL・Googleカレンダーの取り込み」の欄に、Zoom Revenue Acceleratorの要約を貼り、「要約を解析して発注書に反映」を押します。右の発注書プレビューが埋まります。(「Zoomの商談内容」の欄(文字起こしの貼り付け)は、画面から外しました)
3. 抽出結果を目視で確認・修正します(必須項目の未入力は赤い「未確定(要確認)」で表示)。
4. 「HubSpotにチケットを作成して転記」を押すと、発注書が新しいチケットとして作られ、指定した取引と会社に紐づきます。

### 画面の構成
- 上部: ツール名、選んだ商材、「案件を選び直す」。
- 左: ①Zoom要約・URL・Googleカレンダーの取り込み(常に表示)、②HubSpot接続設定(折りたたみ)。PCでは、スクロールしても左が追従します。
- 右: ④発注書プレビュー。基本情報のあと、セクションごとのカードに分かれます。横に並んだ欄は2列で、対象外のセクション(例: フルパック以外のAUTO関連)は畳んで表示し、見出しを押すと開閉できます。
- 右下: 操作バー(不足確認文のコピー、発注書のコピー、HubSpotへ転記)は、スクロールしても画面下に固定されます。
- 必須項目は、解析する前は「*」だけ表示します。解析(または不足確認文のコピー)をすると、未入力の必須項目が「未確定」として強調されます。
- スマホ幅では1列になります。画面のスタイルは、このファイル内のCSSで定義していて、Tailwind(CDN)が読み込めなくても崩れません。

### 商材ごとのプレビュー項目
- **nest**: nestの発注ひな形の全項目(受注・販促商品/nest本体/AUTO/AIO/AIO-RAQMO付/イレギュラー)。契約プランに応じて必須項目が変わります。更新頻度は言及がなければ「半年」。
- **RAQMO**: 制作発注の項目(案件概要・ターゲット・トンマナ・参考URL・提供素材)と、販促(MEETO・MOEL・MOFUL)の詳細。●をつけた販促だけ詳細が必須になります。
- **その他**: 制作発注の項目のみ。

### 自動解析の考え方
- 文字起こしの話者を「営業」「お客様」に分け、**お客様の発言を優先**して項目を埋めます。話者の役割は画面で変更でき(変更後は「自動解析」を押し直す)、「担当営業」と同じ名前の話者は営業とみなします。
- **営業が提案し、お客様がうなずいた内容**(「はい」「そうですね」「お願いします」などの返事)は、お客様の希望として案件概要・ターゲット・トンマナに採用します。「いえ」「ちょっと違う」「検討します」など、否定・保留の返事が付いた提案は採用しません。うなずきは、直前の営業の発言だけに対するものとして扱います。
- 拾った発言は、発注書に載せて意味が通る言い切りの文に整えます(例: 「えーと、ターゲットは学生さんですよね。」→「ターゲットは学生さんです。」、「〜ということでよろしいでしょうか」→「〜」)。長い文は読点の位置で省略します。
- Zoomの字幕が1文の途中で区切られている場合は、同じ話者の続きの字幕をつないで1文に戻して解析します。
- 手入力した欄は、文字起こしを貼り直しても上書きしません(自動入力のままの欄は更新されます)。複数行の欄は内容に合わせて高さが広がります。
- nestでは、業種・事業内容・店舗情報(住所・営業時間の語尾は整形)・SNSを「やっていない」場合の「なし」・GBPのオーナー権限・公式LINEの登録状況も拾います(営業の確認の質問だけでは埋めません)。
- 解析は、すべてブラウザ内のルール処理で、AI(トークン)も外部送信も使いません(AI関連の機能は削除しました)。
- KIZUNAのサービス紹介・料金の説明は、案件概要などに入れません。お客様の発言が無い項目は、営業の「お客様向けの提案」を `【営業発言】` と明記して補います。それも無い項目は空欄のまま(未確定)にします。
- ログイン用メール・パスワード等の認証情報は自動抽出しません。

### Googleカレンダー・ドライブの連携(案件の商談ノートの取得)
**商材を選んだ後の画面の「Zoom要約・URL・Googleカレンダーの取り込み」**の「Googleカレンダー・ドライブから案件の商談ノートを取得」で、カレンダーの予定から案件を選び、その案件の商談ノート(Googleドキュメント)をドライブから探して、発注書の欄に取り込みます。**サーバーは要りません**(ブラウザからGoogleに直接ログインして、読み取るだけです。書き込み・削除はしません)。
- 使い方(商材を選んだ後の画面で): クライアントIDを入れて「ログインして予定を取得」→ 案件(予定)を選ぶ(検索語は、予定のタイトルの顧客名が入ります。直せます)→「商談ノートを探す」→ ノートを選んで「この商談ノートを取り込む」。ノートが無いときは「予定だけ取り込む」。取り込んだ内容は「案件の資料の取り込み」の欄に入り、**そのあと下の商材(nest / RAQMO)を選ぶと、発注書の欄に反映されます**。(URLに `?product=` を付けて開くと、起動画面を飛ばすため、この取り込みは使えません。)
- カレンダーの選び方: 営業の予定が営業ごとの共有カレンダー(例: 「+ID_○○D」)に入っている場合は、「カレンダー」の欄で、そのカレンダーを選びます(選んだカレンダーは覚えます)。予定が多いときは、「予定の絞り込み」に顧客名・担当名を入れます。
- 予定の題名から顧客名を読み取る形: 「◎❷担当/ZDn(AF)/有限会社○○/同席者」「担当・担当・○○株式会社様：済み」「【商談】○○様 打ち合わせ」。ドライブの検索語は、法人格(株式会社など)を除いた名前です(書類の題名が「○○様_商談②_日付_担当」の形のため)。
- 予定の説明(事前ヒアリング)から読み取る項目: 業種・店舗名・所在地・電話・Instagramの運用状況(有/無)・Googleマップ(GBP)の自社管理状況(自社→あり)・「その他情報」(お店の課題など)。**説明欄のHubSpotのリンク(…/record/0-3/数字)から、取引IDも自動で入れます**。代表名・メールアドレス・アポの前提条件などは、発注書に不要なので読みません。
- 反映のしかた: 予定のタイトル(顧客名)・説明欄と、商談ノートの本文を、下の「読み取りのルール」で読みます(「強み: 〜」「■困りごと」などのラベル、URL、Instagramなど)。手入力した欄は上書きしません。
- 送る情報: Googleへは、ログインのトークン、日付の範囲、検索語(顧客名など)、ファイルIDだけです。発注書の内容は送りません。ログインを押すまでは、Googleへ何も送りません(ログイン用スクリプトも読み込みません)。
- **準備(1回だけ。Google Workspaceの管理者の確認が必要なことがあります)**:
  1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作り、「APIとサービス」で **Google Calendar API** と **Google Drive API** を有効にする。
  2. 「OAuth同意画面」を設定する。会社のGoogle Workspaceのアカウントだけで使うなら、ユーザーの種類は「内部」(審査が不要)。**個人のGmail(`@gmail.com`)のアカウントで使う場合は「内部」にできない(`org_internal` エラーになる)ので、「外部」+公開ステータス「テスト中」にして、使う人のGmailを「テストユーザー」に追加する**(最大100人。審査は不要。許可は7日で切れるので、そのときはログインし直す)。スコープは、全文で `https://www.googleapis.com/auth/calendar.readonly` と `https://www.googleapis.com/auth/drive.readonly` を追加する。
  3. 「認証情報」→「OAuthクライアントID」→ 種類「ウェブアプリケーション」を作る。「承認済みのJavaScript生成元」に、ツールを開くURLの元(例: `https://kizunayyamamoto-afk.github.io`。手元で試すなら `http://localhost:8000`)を入れる。
  4. 表示された **クライアントID**(`〜.apps.googleusercontent.com`。秘密の値ではありません)を、ツールに入れる。
- うまくいかないとき: 「ログインできません」→ クライアントIDと、承認済みのJavaScript生成元を確認。HTTP 403 → 2つのAPIが有効か、同意画面のスコープを確認。「見つかりません」→ 検索語を変える(顧客名の表記違い)。
- 注意: 商談ノートに、お客様の情報が含まれます。ツールを開く人を、社内に限ってください。

### Zoom Revenue Acceleratorの要約を貼る(最初の画面)
Zoom Revenue Acceleratorの要約は、自動では取得しません(取得機能は削除しました)。**起動画面の一番上の「Zoom Revenue Acceleratorの要約」の欄に、要約をコピーして貼ります**。商材を選ぶと、そのまま解析して、発注書の欄に入れます。
- 手順: ZoomのRevenue Acceleratorで、商談の要約を開く → コピー → 商材を選んだ後の画面の「Zoom要約」の欄に貼る → 商材(nest / RAQMO)を選ぶ。
- 文字起こし(.vtt / .txt)を貼る欄は、画面から外しました。要約を貼ってください。

### 読み取りのルール(Zoomの要約・カレンダーの予定・商談ノート・HubSpotの情報)
貼り付けた要約や、Googleカレンダー・ドライブ、HubSpotから取り込んだ内容は、ブラウザの中の、次のルールで読みます。
- **Zoomの要約**(商材を選んだ後の画面の「Zoom要約」の欄に貼り「要約を解析して発注書に反映」を押す): そのまま解析します。「概要:」「次のステップ:」などの見出しは話者として扱わず、「お客様は〜と述べました」「〜とのことです」は言い切りの文に整えます。
- **Googleカレンダーの予定**: タイトルから顧客名を取り出します。説明欄の「ラベル: 値」とURLも読みます。ZoomやGoogle MeetのURLは使いません。
- **商談ノート**: 「強み: 〜」「【困りごと】〜」「■強み」の次の行、の形の項目を、該当の欄に入れます(業種・事業・強み・困りごと・案件概要・ターゲット・トンマナ・提供素材・住所・電話・営業時間・サイト・Instagram・X・Facebook・Googleマップ)。「Instagram: @アカウント名」はURLにします。「Facebook: なし」は「なし」にします。ラベルの無い文章は、要約と同じルールで読みます。
- 優先順位: 商談ノート > カレンダー > HubSpot。手入力した欄は上書きしません。文字起こしを解析すると、その内容で更新されます(検出できなかった項目は、取り込んだ内容のまま残ります)。
- 商材を選んだ後の画面の「お客様に見せたURL」に貼ったURL(資料・サイト・Instagram・X・Facebook・Googleビジネスプロフィール)は、種類を自動で振り分けて、該当の欄に入れます。
- なお、起動画面の「Googleマップの情報を読み取る」と「案件の資料を取り込む」(カレンダーの予定・商談ノートを貼る欄)は、削除しました。予定・商談ノートは、Googleカレンダー・ドライブの連携で取り込みます。

### HubSpotにある情報の取得(読み取りのみ・会社と取引だけ)
右カラムの「HubSpot 紐づけ先」の「**HubSpotの情報を取得して反映**」で、取引IDから、HubSpotにある**会社情報と取引情報**を読み取ります(書き込みはしません。担当者・ノートは読みません)。
- 取得するもの: 取引(取引名・ステージ・説明)と、取引に紐づく会社(会社名・電話・住所・郵便番号・サイト)。画面に表示し、会社IDも自動で入れます。
- 発注書への反映: 会社名→顧客名・店舗名、電話・住所・郵便番号・サイト、取引や会社の説明にある「強み: 〜」「困りごと: 〜」などを、資料の取り込みと同じルールで欄に入れます。手入力した欄は上書きしません。優先度は、商談ノート > カレンダー > HubSpot の順です。
- 自動取得: Googleカレンダーの予定の説明にHubSpotのリンク(`…/record/0-3/数字`)があると、取引IDが自動で入ります。このとき、HubSpotのトークンが設定済みなら、商材を選んだ時点で、HubSpotの情報も自動で取得します。
- 送る情報: HubSpotへは、取引ID・会社IDだけです。発注書の内容は送りません。
- **費用**: Private Appの作成と、このAPIでの読み取りに、追加料金はかからない見込みです(HubSpotの公式の説明で確認してください)。無料・Starterのプランでは、1アプリあたり10秒に100回、アカウントで1日25万回までの上限があります(1回の取得は2回の呼び出しです)。
- Private Appに必要な権限(スコープ。中継サーバーに設定するトークンの権限です): `crm.objects.deals.read` と `crm.objects.companies.read` の2つだけです。チケットへの転記には、これまでどおり `tickets` の書き込みも必要です。
- **中継サーバーが必要です**: HubSpot APIは、ブラウザから直接は呼べない(CORS。「Failed to fetch」と出る)ため、読み取りも転記も、無料の中継サーバー(Cloudflare Workers)を経由します。作り方は [relay/hubspot/README.md](relay/hubspot/README.md)。左カラム「HubSpot接続設定」に、中継サーバーのURLと合言葉を入れます(HubSpotのトークンは、中継サーバー側にだけ置きます)。

### 設定済みのリンク(HubSpotの接続設定を、開くだけで入れる)
- 中継サーバーの**URLは、初めから入っています**(秘密ではないため、コードに入れています)。**合言葉は、コードには入れていません**(公開のリポジトリで、誰でも読めてしまうため)。
- 使う人に、合言葉を入れてもらう代わりに、「**設定済みのリンク**」を渡せます。作り方: 管理者が、「HubSpot接続設定」にURLと合言葉を入れて、「**設定済みのリンクをコピー**」を押します。コピーされたリンク(`…/#relay=…&key=…`)を、社内の人に渡します。
- リンクを開くと、URLと合言葉が入った状態になり、アドレスバーから「#」以降(合言葉)が消えます。「#」以降は、サーバーには送られません。入れた値は、「保存する」にチェックしない限り、そのブラウザに保存されません(保存しない場合は、開き直すたびに、リンクを開き直します。ブックマークしても使えます)。
- **リンクは、合言葉と同じ扱い**です。社内の決まった場所(パスワード管理ツールなど)にだけ置き、公開の場所やお客様には、渡さないでください。合言葉を変えたときは、リンクも作り直して、配り直します。

### HubSpotへの転記
- **取引ID(必須)**: 発注書のチケットを紐づける取引。HubSpotの取引画面のURL末尾の数字です。
- **発注書の入れ先**: 「HubSpot接続設定」の「発注書の内容を入れる場所」で、「チケットのメモだけ」(初期値。チケットの説明は空)、「説明とメモの両方」、「説明だけ」を選べます。メモは、チケットに紐づく**メモ(ノート)**として作られ、チケットの画面の「メモ」の欄に出ます。メモの作成には、Private Appに、ノート(メモ)の作成の権限が必要です(足りないと、チケットは作られ、メモだけ作られず、画面に案内が出ます)。
- **会社ID(任意)**: 空にすると、取引に紐づく会社を自動で取得します。
- 接続設定(中継サーバーのURLと合言葉、チケット本文のプロパティ名、パイプラインID、ステージID)は、左カラム「HubSpot接続設定」。

### 実行・技術・注意
- 実行: `index.html` をブラウザで開くだけ(Node.js・サーバー不要)。
- 技術: HTML / Tailwind CSS(CDN) / 素のJavaScript。抽出はルールベースで、AIは使いません(外部通信は、HubSpotの中継サーバー経由の読み取り・転記と、任意のGoogleカレンダー・ドライブの取得のみ)。
- 中継サーバーのURLと合言葉は、画面で一時入力、またはブラウザのLocalStorageに保存します(HubSpotのトークンは、中継サーバー側にだけ置き、ブラウザには置きません)。
- 中継サーバーに接続できないときは、「発注書をコピー」で、HubSpotのチケットへ手で貼れます。

## 秘密情報の扱い
APIキーやトークンはリポジトリにcommitしないでください。`.env` は `.gitignore` 済みです。

## 発注書変換スキル(Claude Code)
Zoom文字起こしを発注書に変換する、**種類別の専用スキル**です。種類ごとに完全に分離しており、書式・ルールは混ざりません。

| コマンド | 対象 | 見出し |
|---|---|---|
| `/order-raqmo` | RAQMO(制作発注) | 【制作発注】 |
| `/order-nest` | nestの発注 | 【nestの発注】 |

- 使い方: `/order-nest` の後ろに文字起こしを貼る(または実行後に貼る)。出力は「発注書本文」と「要確認リスト」。
- 自動では起動しません(`disable-model-invocation`)。必ずコマンドで種類を選んでください。
- 場所: `.claude/skills/order-raqmo/` と `.claude/skills/order-nest/`(各 `SKILL.md`=変換ルール、`template.md`=書式、`learning.md`=過去事例の学習メモ)。
- 種類の見分け方: 「nest / フルパック / AIO / 口コミ誘導」が出ればnest、「ドメイン / MEETO / MOFUL / サイト名」が出ればRAQMO。
- nestにRAQMO-LP(AIO付)が付く場合は、nestの発注書内の【AIO-RAQMO付の場合】欄に書きます(RAQMO書式は使わない)。別契約なら2通に分けて作成します。
- パスワードの扱いは種類で異なります(RAQMO=書かない、nest=お客様が明言した場合のみ記入)。発注書には機微情報が入りうるため、Gitや共有チャットに貼らないでください。

## 顧客名からHubSpotの取引IDを探す
発注書の「顧客名」を入れる(または自動で入る)と、HubSpotの取引を顧客名で検索し、取引IDと会社IDを自動で入れます。
- 1件だけ見つかったら、そのIDを入れます。複数なら、候補から選びます。見つからないときは、取引IDを直接入れてください。
- 手入力した取引IDは、上書きしません。

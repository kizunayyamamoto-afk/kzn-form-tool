# nest発注書 学習メモ(過去3件の事例から)
※この資料はnest専用。RAQMO(制作発注)の知識は持ち込まない。
※元データに含まれるメール/パスワード等の実値は、このメモには転記していない。

## 1. nest発注書の目的
nest(AI検索対策・SNS自動運用・口コミ等のコンサル/運用サービス)の**初期設定に必要な情報**を、
運用担当へ引き継ぐ書類。RAQMOがサイト制作の指示書なのに対し、nestは
**アカウント連携・店舗情報登録・計測設定**に必要なデータの完全性が命。

## 2. 構成(全件共通の順序)
1. 受注・販促商品(nest フルパック or 単体 / RAQMO-LP付き有無 / 特別発注)
2. 業種 / 何をしている会社か / 困りごと / 売り・強み
3. ＜nest本体関連＞ 店舗名、ログイン希望メール・PW、更新頻度、登録希望サイトURL、nest公式LINE登録
4. ＜nest for AUTO関連＞ SNS(Facebook/Instagram/X)とGBP(オーナー権限、KIZUNAへの権限付与)
5. ＜nest for AIO関連＞ 店舗情報(店名/電話/郵便/住所/営業時間)、登録サイト(KIZUNA作成or顧客保有、GA4)、他媒体掲載状況
6. 【AIO-RAQMO付の場合】 サイト関連一式(RAQMO-LP AIO付がある時のみ)
7. ＜この案件に対するイレギュラー対応共有＞

## 3. 重要度ランク
### S: 抜けると初期設定が止まる
- 契約プラン(フルパック/単体)と、RAQMO-LP付きの有無
- GBPの有無・オーナー権限の有無・**KIZUNAへの権限付与状況(済/未、日付、担当)**
- 店舗情報(店名の正式表記、電話、〒、住所、営業時間)
- 登録希望WebサイトURL(KIZUNA作成/顧客保有/制作中/なし)
- 連携するSNSの有無とURL
- ログイン希望メール・パスワード(8文字以上の半角英数字)※契約時確認ならその旨
- 更新頻度(毎月/半年/一年)

### A: 精度に効く
- 屋号・店名の表記ゆれ(正式表記と混在パターン)→AI検索で正しく認識されない原因
- 複数店舗の有無と紐付け
- GA4設定有無、サイトの保有者
- 他媒体の掲載状況(Googleマップ/Yahoo/食べログ/トリップアドバイザー/Apple Business Connect/エキテン/iタウンページ/業種別)
- nest公式LINEの登録状況(回収日が決まっていればその日付)
- 困りごと(具体的に)、売り・強み

### B: 運用・関係構築
- 窓口担当と最終決裁者、リテラシー、反応(好反応の発言引用)
- 多忙さ・連絡手段(電話/LINE/Zoom)、従業員へのレクチャー要否
- 他社サービスとの併用(例: サイトは他社、SNS・口コミはnest)
- 補助金の検討(事前着手禁止など制約)
- 新事業開始など時期的な事情

## 4. 書き方の傾向
- 未確認は「契約時に確認予定」「未言及」「不明」「ー」と明示(空欄より親切)
- 後から判明した情報は「旧 → 新」+日付+担当者で追記(例:「否 → ○年○月○日付与済(担当名)」)
- 他媒体は「掲載あり(評価/件数)」まで書く
- イレギュラー欄は 窓口/リテラシー/反応/デモ時詳細 などの小見出しで整理すると読みやすい
- フルパックのとき、単体欄は「–」か空欄

## 5. 過去データの品質の揺れ(変換時に防ぐ)
- 「強み」欄に課題(困りごと)が混入していた → 厳禁
- 「困りごと」欄が空で、内容が別欄に混ざっていた(改行崩れ)
- 電話番号がGoogle検索URL付きリンクになっている → 数字のみの平文にする
- 「24時間？」など曖昧な営業時間 → 【要確認】を付ける
- マークが「◉」「●」で揺れる → 「●」に統一
- 【AIO-RAQMO付の場合】が空欄のまま/「該当なし」の理由が無い → 付かない場合は「該当なし(理由)」と明記
- 見出しが「【nestの発注】」「制作発注書」などで揺れる → 「【nestの発注】」に統一
- 「店名」が株式会社名と屋号で食い違う → 正式表記と表記ゆれを併記し【要確認】

## 6. 認証情報の扱い(nest特有)
- 「ログインに必要なお客様希望メール/パスワード」はnest発注の**正式な入力項目**。商談内で顧客が明言したときのみ記入。
- 決まっていなければ「契約時に確認予定」。作り話の値を入れない。
- SNSのパスワードは、顧客が明言した場合のみ。無ければ「ヒアリング」。
- パスワードを記載した場合は、要確認リストに【機微情報あり・取扱注意】を必ず出す。
- パスワード形式(8文字以上・半角英数字)を満たさない場合は【要確認】。

## 7. Zoom文字起こし特有の注意(nest)
- 固有名詞(屋号・人名・住所・電話)は誤変換しやすい → 【要確認】
- 電話番号・郵便番号・メールアドレスは音声の聞き違いが多い → 【要確認】
- 「Googleに権限を渡す」操作は口頭で済ませがち。**付与済か未かを最後の発言で判定**
- 会議後に追記された確認事項(日付付き)がある場合は反映
